API playground

Build a real request against any of the — documented operations. Settings persist in this browser's localStorage; nothing is sent anywhere except the base URL you configure.

CORS is required and not on by default. Browsers enforce the same-origin policy: this playground can only call an API deployment that returns Access-Control-Allow-Origin for the portal's origin (and allows the Authorization / X-API-Key headers via Access-Control-Allow-Headers). The Go API does not enable cross-origin browser access out of the box — if requests fail with a CORS error, drive the API with agentosctl or curl instead, or front both the portal and the API with the same reverse proxy so they share an origin.

SDKs & CLI

Three supported ways to talk to the API: the typed Go SDK, the agentosctl CLI, and generated Python/TypeScript clients.

Go SDK — internal/sdk

A stdlib-only, typed client that mirrors the HTTP surface in api/openapi.yaml. It lives in the agentos module (importable from code inside this repository — cmd/agentosctl is built on it; extracting it into a standalone public module is tracked separately). It handles both credential styles, the API's mixed envelope shapes (bare arrays/objects and wrapped envelopes), and the structured error model. 

gopackage main

import (
        "context"
        "fmt"
        "log"
        "time"

        "agentos/internal/sdk"
)

func main() {
        ctx, cancel := context.WithTimeout(context.Background(), 30*time.Second)
        defer cancel()

        client := sdk.New(
                sdk.WithBaseURL("http://localhost:8080"), // default; /v1 prefixing is handled
                sdk.WithToken("eyJhbGciOi…"),             // bearer from POST /v1/auth/login
                // or: sdk.WithAPIKey("ak_…")            // X-API-Key self-service key
        )

        // Create an agent (POST /v1/agents/create → 201, bare Agent object).
        agent, err := client.CreateAgent(ctx, sdk.CreateAgentRequest{
                Name:         "Support Agent",
                Instructions: "Answer customer questions concisely",
                Model:        "gpt-4o-mini",
        })
        if err != nil {
                log.Fatal(err)
        }

        // Create and enqueue a run (POST /v1/runs → 201 {run_id, status}).
        run, err := client.CreateRun(ctx, sdk.CreateRunRequest{
                AgentID: agent.ID,
                Input:   "What is 2+2?",
        })
        if err != nil {
                log.Fatal(err)
        }
        fmt.Println("run", run.RunID, run.Status)

        // Stream execution events (GET /v1/runs/{id}/events, text/event-stream).
        events, err := client.StreamEvents(ctx, run.RunID)
        if err != nil {
                log.Fatal(err)
        }
        defer events.Close()
        for {
                ev, err := events.Next()
                if err != nil {
                        break // io.EOF when the run finishes
                }
                fmt.Println(ev.Type, ev.StepID)
        }
}

Coverage today: agents, runs (create/get/list/steps/SSE stream), auth (login/register), API keys, workflows (create/execute/get run), knowledge, billing, usage costs, secrets, marketplace, connectors, SSO/SCIM. Every method takes a context.Context and honours cancellation; inject a custom transport with sdk.WithHTTPClient.

CLI — agentosctl

Build it from a repo checkout (the binary lives at cmd/agentosctl):

bashgo build -o agentosctl ./cmd/agentosctl

# Configuration: env AGENTOS_URL / AGENTOS_TOKEN / AGENTOS_API_KEY
# override the profile written to ~/.agentos/config.json by `login`.
./agentosctl register -org "Acme AI" -email dev@example.com -password s3cret   # first OWNER user
./agentosctl login -email dev@example.com -password s3cret

./agentosctl agents create -name helper -instructions "be brief" -model gpt-4o-mini
./agentosctl agents run AGENT_ID "what is 2+2?"
./agentosctl runs watch RUN_ID          # follows the SSE event stream
./agentosctl usage costs -group-by agent
./agentosctl api-keys create -name ci-deploy

# Every command accepts -json (before or after the command) for scripts:
./agentosctl agents list --json

Generate a Python or TypeScript client

The spec is the single source of truth, so generated clients stay honest. Generate them yourself with openapi-generator — generated SDKs are intentionally not vendored in this repository: 

bash# Prerequisite: openapi-generator-cli on PATH (npm i -g @openapitools/openapi-generator-cli)

# Python (urllib3 transport, stdlib-friendly)
openapi-generator-cli generate \
  -i api/openapi.yaml \
  -g python \
  --library urllib3 \
  --package-name agentos_client \
  -o sdks/python

# TypeScript (fetch runtime, works in browsers and Node 18+)
openapi-generator-cli generate \
  -i api/openapi.yaml \
  -g typescript-fetch \
  --npm-name @agentos/api-client \
  -o sdks/typescript

# Alternative TS runtime: -g typescript-axios (npm axios) or -g typescript-node.
Spec-first rule: regenerate clients after any contract change; never hand-edit generated output. The portal's own reference data is regenerated the same way — python3 scripts/gen_portal_docs.py.

5-minute quickstart

Register → create an agent → run it → watch it work. Every step below hits an endpoint documented in the reference (auth, agents, runs groups).

Zero-infra mode: the API runs fully in-memory with an offline deterministic model provider when no model credentials are configured, so this quickstart works on a laptop with no database and no LLM keys. Start it with go run ./cmd/api (default listen :8080).

1 — Register the organization's first OWNER user

bashcurl -s http://localhost:8080/api/v1/auth/register \
  -H 'Content-Type: application/json' \
  -d '{"organization":"Acme AI","email":"owner@acme.dev","password":"s3cret-password"}'
# 201 → {"organization":{"ID":"org-1","Name":"Acme AI"},"user":{...}}

2 — Log in and grab the bearer token

bashTOKEN=$(curl -s http://localhost:8080/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"owner@acme.dev","password":"s3cret-password"}' | python3 -c 'import json,sys; print(json.load(sys.stdin)["token"])')
# Token is HMAC-SHA256 JWT-style, 24h expiry. Use: Authorization: Bearer $TOKEN

3 — Create an agent

bashcurl -s http://localhost:8080/api/v1/agents/create \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"name":"Support Agent","instructions":"Answer questions concisely","model":"gpt-4o-mini"}'
# 201 → Agent object (PascalCase keys): {"ID":"agent-1","Status":"DRAFT",...}
AGENT_ID=$(... | python3 -c 'import json,sys; print(json.load(sys.stdin)["ID"])')

Required fields: name, instructions, model (server-validated; 400 otherwise). The agent starts in DRAFT with an initial version 1.

4 — Run it

bashcurl -s http://localhost:8080/api/v1/runs \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"agent_id":"'"$AGENT_ID"'","input":"What is 2+2?"}'
# 201 → {"run_id":"…","status":"queued"}   (execution happens on the worker)

5 — Watch events / inspect the result

bashcurl -s -N http://localhost:8080/api/v1/runs/$RUN_ID/events \
  -H "Authorization: Bearer $TOKEN"
# text/event-stream: data: {"type":"step.started",...} … until terminal status

curl -s http://localhost:8080/api/v1/runs/$RUN_ID      -H "Authorization: Bearer $TOKEN"   # final run object
curl -s http://localhost:8080/api/v1/runs/$RUN_ID/steps -H "Authorization: Bearer $TOKEN"   # per-step timeline

CLI equivalent

bashagentosctl register -org "Acme AI" -email owner@acme.dev -password s3cret-password
agentosctl login -email owner@acme.dev -password s3cret-password
agentosctl agents create -name helper -instructions "be brief" -model gpt-4o-mini
agentosctl agents run AGENT_ID "what is 2+2?"
agentosctl runs watch RUN_ID

Orchestration tutorial — agent-to-agent delegation

AgentOS ships a supervisor/delegation executor: agents talk over an org-scoped message bus, and a delegator can hand a subtask to another agent, synchronously awaiting the response in its inbox.

1 — Two agents

Create a delegator and a worker (repeat the quickstart's step 3 twice), e.g. orchestrator and researcher.

2 — Delegate a subtask

bashcurl -s http://localhost:8080/api/v1/orchestration/delegate \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{
        "from_agent_id": "agent-orchestrator",
        "to_agent_id":   "agent-researcher",
        "task":          "Summarize the incident timeline",
        "parent_run_id": "",
        "require_approval": false,
        "depth": 0
      }'
# 202 → {"delegation_id":"…","child_run_id":"…","status":"pending","depth":0}

The call returns 202 immediately: without require_approval the child run executes in the background and the outcome lands in the delegator's inbox as a response message. With require_approval: true the delegation parks at the approval gate (status: "awaiting_approval", approval_id set) and never executes until an operator approves it. Depth limits are enforced server-side; the ledger keeps the delegation traceable across 4xx/5xx failures.

3 — Read the delegator's inbox

bashcurl -s "http://localhost:8080/api/v1/orchestration/agents/agent-orchestrator/messages?limit=20" \
  -H "Authorization: Bearer $TOKEN"
# newest-first retained inbox for the caller's organization

For point-to-point messaging without a child run, use POST /orchestration/messages (message_type: request, response, delegate, or broadcast — a saturated inbox answers 409 INBOX_FULL and may be retried). Supervisor strategies (round-robin / least-loaded / capability-match) are exposed at POST /orchestration/supervisor/run. Requires the orchestration.write / orchestration.read permissions.

Workflow tutorial — create, validate, run

Workflows are JSON-DSL graphs of agent, approval, and control-flow nodes executed durably with checkpoints. This tutorial validates a DSL, persists it, and executes it.

1 — Validate the DSL before saving (stateless)

bashcurl -s http://localhost:8080/api/v1/workflows/validate \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{
        "dsl": {
          "nodes": [
            {"id":"n1","type":"agent","name":"Planner","config":{"agent_id":"agent-1","input":"{{input}}"}},
            {"id":"n2","type":"approval","name":"Gate","config":{"action":"deploy","risk":"high"}}
          ],
          "edges": [ {"from":"n1","to":"n2","condition":"on_success"} ]
        }
      }'
# 200 → {"valid":true}   |   422 → {"errors":[{"code","message","node_id"}]}

2 — Create the workflow (runs validation again)

bashcurl -s http://localhost:8080/api/v1/workflows/create \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"name":"Deploy Flow","description":"Plan then deploy with a sign-off gate","dsl":{…same dsl…}}'
# 201 → WorkflowDetailResponse (draft, current_version 0)
# invalid DSL → 422 with the typed error list (empty_graph, duplicate_node_id,
# unknown_node_type, cycle_detected, invalid_edge_condition, …)

3 — Execute

bashcurl -s http://localhost:8080/api/v1/workflows/$WORKFLOW_ID/execute \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"input":"Deploy the payments service"}'
# workflow run id + queued status; approval nodes park at WAITING_APPROVAL

curl -s http://localhost:8080/api/v1/workflow-runs/$WORKFLOW_RUN_ID       -H "Authorization: Bearer $TOKEN"  # status
curl -s http://localhost:8080/api/v1/workflow-runs/$WORKFLOW_RUN_ID/nodes -H "Authorization: Bearer $TOKEN"  # per-node timeline

Optionally re-validate the persisted draft with POST /workflows/{id}/validate (same error shape), and list executions with GET /workflows/{id}. Control-flow node types (if/switch/loop/retry/wait) take typed expressions validated server-side; parallel branches support all/any/race/majority aggregation.

Where releases live

Releases, tags, and per-release notes are published on GitHub:

github.com/Roy-Wanyoike/AI-Agentic-Infrastructure-Platform/releases ↗

API changes are summarized in the release notes of the version that ships them.

API versioning policy

  • The contract is semver-versioned in api/openapi.yaml (info.version, currently —). MAJOR = breaking, MINOR = additive, PATCH = docs/fixes.
  • The canonical base path is /api/v1. A legacy root that serves identical /v1/* routes exists for old clients and is deprecated — new integrations must use /api/v1.
  • Additive changes (new optional fields, new endpoints, new enum members that are documented as open) may land in MINOR releases without notice. Clients must ignore unknown JSON fields.
  • Breaking changes ship only in MAJOR versions and are announced at least one MINOR ahead in release notes.
  • Known current limitation, tracked in the spec with x-unpaginated: list endpoints (GET /agents, GET /runs) return full result sets today and will gain pagination in a future MINOR.
  • Some legacy handlers still return text/plain errors; the structured {"error":{"code","message","request_id"}} envelope is the authoritative model for new code.
