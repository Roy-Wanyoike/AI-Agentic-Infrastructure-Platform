# Track 2-h — Observability + DX wiring notes

Track branch: `feat/wave2-observability`. No migration. No new Go module
dependencies.

## /metrics re-registration (orchestrator action)

The new Prometheus-text-by-default handler lives in `cmd/api/metrics_v2.go`
(`cmd/api/handlers.go` was NOT touched). Swap the existing `/metrics`
registration in `cmd/api/main.go` (`routes()`):

```go
// BEFORE (current):
apiMux.Handle("/metrics", auth.RequireAuthOrAPIKey(a.authSvc, a.apiKeysSvc)(auth.RequirePermission(a.authSvc, auth.PermissionRunsRead)(http.HandlerFunc(metricsHandler(a.metricsSvc, a.queueSvc)))))

// AFTER (drop-in replacement, same deps):
apiMux.Handle("/metrics", auth.RequireAuthOrAPIKey(a.authSvc, a.apiKeysSvc)(auth.RequirePermission(a.authSvc, auth.PermissionRunsRead)(http.HandlerFunc(metricsV2Handler(a.metricsSvc, a.queueSvc)))))
```

`metricsHandler` in `cmd/api/handlers.go` becomes dead code after the swap; it
can be deleted in a later cleanup commit together with any references in
`cmd/api` tests that intentionally still exercise the legacy handler.

Behavior of `metricsV2Handler`:

- `GET /metrics` (default): Prometheus TEXT exposition (version 0.0.4),
  `Content-Type: text/plain; version=0.0.4`. Families emitted from recorded
  data include `agentos_runs_total`, `agentos_tools_total`,
  `agentos_request_duration_seconds_bucket{route=...,method=...,status=...,le=...}`
  (+ `_sum`/`_count`), `http_requests_total{...}`, `agentos_queue_length`.
- `GET /metrics?format=json`: the legacy JSON payload — `counts`, `latency`,
  `queue_length` keys unchanged — plus an additive `histograms` map with
  `count/sum/min/max/p50/p95/p99/buckets` per series.

## Optional one-line counters for run/tool creation

`observability.Metrics` gained `IncRuns()` (`agentos_runs_total`) and
`IncTools()` (`agentos_tools_total`). To give these real data, the orchestrator
may add one line each to the create-run / tool-execution handlers:

```go
// in createRunHandler (cmd/api/runs.go) after a successful create:
//   (needs the *observability.Metrics passed in — orchestrator wiring)
a.metricsSvc.IncRuns()
```

Until wired, those families only appear on /metrics once something increments
them (they are not emitted when empty, except `agentos_queue_length` which is
always rendered when a queue is present).

## New observability API surface

- `observability.Metrics.ObserveHistogram(name, value)` — bucketed observation
  (default Prometheus buckets, lazy histogram creation).
- `observability.Metrics.SnapshotSummaries() map[string]HistogramSummary` —
  p50/p95/p99/count/sum/min/max/buckets per series.
- `observability.Metrics.ObserveHTTP(...)` now additionally records a bucketed
  observation into `agentos_request_duration_seconds{route,method,status}` per
  request (existing last-value gauge behavior unchanged).
- `observability.RenderPrometheusText(counts, latency, summaries, queueLength)` —
  pure renderer; `queueLength < 0` omits the queue gauge.
- `observability.PrometheusFormat` = `"text/plain; version=0.0.4"`.

## cmd/seed

`cmd/seed` is self-contained (no wiring into the API). Run with
`make seed` / `go run ./cmd/seed` after `make migrate-up`. Env knobs:
`DATABASE_URL` (default `postgres://agentos:agentos@localhost:5432/agentos?sslmode=disable`),
`AGENTOS_SEED_PASSWORD` (default `demo-password`). Idempotent: re-running
skips existing entities. Wave-2 optional tables (e.g. `eval_datasets` from
migration 009) are skipped with a warning when their migration has not been
applied yet.
